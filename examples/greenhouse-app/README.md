# Autonomous Greenhouse Reflex Controller

Demonstrates real-time sensory evaluation, Vapor Pressure Deficit (VPD) regulation, and safety-gated actuation proposals over na8ve-os Inter-Process Communication.

## Files

* `greenhouse.c`: Application logic executing inside the sandboxed WebAssembly execution environment.
* `test_greenhouse.c`: Native host test harness validating positive behavior and negative control twin (`-DEXPECT_MISMATCH`).
* `manifest-entry.json`: Capability manifest declaring execution parameters, linear memory budget, and sensor grants.
* `greenhouse_sim.py`: Automated hybrid simulation daemon combining continuous environmental physics with the native C cognitive engine.

## Native Host Testing

Verify the application logic locally on your developer machine:

```bash
# Run positive test suite
gcc -I../../sdk/include greenhouse.c test_greenhouse.c ../../sdk/src/n8_util.c -o test_greenhouse
./test_greenhouse
# Expected output:
# ok ping
# ok normal environment (0 actuations)
# ok alert environment (2 actuations dispatched: fan and misting pump)
# PASSED

# Run negative control twin (must fail without alert handling)
gcc -DEXPECT_MISMATCH -I../../sdk/include greenhouse.c test_greenhouse.c ../../sdk/src/n8_util.c -o test_greenhouse_control
./test_greenhouse_control
# Expected output:
# control: expected mismatch; caught=1
```

Compile and sign using the na8ve-os Application SDK tooling:

## Hybrid Cognitive-Physics Architecture

The automated simulation daemon (`greenhouse_sim.py`) implements a **Hybrid Cognitive-Physics Engine**, coupling continuous thermodynamic microclimate physics with the native C cognitive engine (`console_host_greenhouse`):

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │              na8ve-tui / na8ve-console (TCP 127.0.0.1:7878)            │
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │ TCP Socket Link
 ┌───────────────────────────────────▼────────────────────────────────────┐
 │            Automated Simulation Daemon (greenhouse_sim.py)             │
 │                                                                        │
 │   ┌───────────────────────────────┐  ┌──────────────────────────────┐  │
 │   │     GreenhouseEnvironment     │  │    CognitiveEngineBackend    │  │
 │   │                               │  │                              │  │
 │   │  • Environmental physics      │  │  • Spawns native C engine:   │  │
 │   │  • Diurnal temperature drift  │  │    console_host_greenhouse   │  │
 │   │  • Humidity accumulation      │  │  • 25 Seed Facts in SQLite   │  │
 │   │  • Root-zone soil ADC         │  │  • Autoregressive byte-level │  │
 │   │  • VPD reflex controller      │  │    neural inference          │  │
 │   │  • Streaming ev tick / act    │  │  • Dynamic model loader      │  │
 │   │  • Dynamic sensor readings    │  │    (/model 3 32 -> .n8vm)    │  │
 │   └───────────────┬───────────────┘  └──────────────┬───────────────┘  │
 └───────────────────┼─────────────────────────────────┼──────────────────┘
                     │                                 │
                     ▼                                 ▼
             Real-Time Sensors                 Real Neural Tokens
              & Reflex Loops                & Critical Context Graph
```

### 1. Cognitive Engine Subprocess (`CognitiveEngineBackend`)
- **Automated Memory Seeding**: On daemon startup, seeds the 25 canonical greenhouse facts (`seed-device.txt`) into the local SQLite graph store.
- **Real Graph Retrieval**: Commands such as `ask what grows in bed-1?` and `call {"tool":"recall",...}` query the SQLite graph, emitting associative entity relations (`bed-1 | grows | basil [m:5]`, `bed-1 | grows | tomatoes [m:6]`, `light | lights | bed-1 [m:18]`, `pump | waters | bed-1 [m:12]`) and vector scores (`vec m=5 distance=29 relevance=0.4081`).
- **Autoregressive Neural Token Generation**: Executes real forward passes with folded graph memory states, streaming generated byte tokens (`b <hex> p=<prob> alt=...`) live over the TCP connection.
- **Dynamic Model Catalog Switching**: Translates `/model 3 32` into `model-load <path> 32`, switching the active model in ~12 ms.
- **Actuator Safety Table**: Loads the compiled 6-actuator table (`fan`, `light`, `buzzer`, `pump`, `vent`, `mister`) and enforces safety interlocks.
- **Live Memory Graph Export**: `export m 0 32`, `export c 0 32`, and `export l 0 32` dump active SQLite memory nodes, concepts, and associative links for graphical rendering in the TUI (F4 view).

### 2. Physics Simulation Model (`GreenhouseEnvironment`)
- **Microclimate Simulation**: Background simulation thread modeling diurnal warming, relative humidity accumulation, misting pulses, capacitive moisture depletion, and exhaust ventilation.
- **Reflex Controller**:
  - High VPD (> 1.40 kPa): Triggers misting pump pulse (`ev reflex rule="vpd_high"`).
  - High Humidity (> 85%): Engages exhaust fan (`ev reflex rule="humidity_high"`).
  - Dry Soil (ADC < 1200): Triggers root-zone irrigation pulse (`ev reflex rule="soil_dry"`).
- **Streaming Telemetry**: Emits live `ev tick ...` lines every 2 seconds, reflecting dynamic physical states.
- **Sensor Readings**: Provides dynamic JSON payloads for `readings` and `call {"tool":"readings_latest",...}`.

## How to Run Directly from na8ve-os

### Terminal 1: Launch the Automated Greenhouse Physics Daemon

From the `na8ve-os` repository root:

```powershell
python examples/greenhouse-app/greenhouse_sim.py
```

> **Note**: If port 7878 is already bound by an active Android Debug Bridge rule (`adb forward tcp:7878 tcp:7878`), clear the forward rule with `adb forward --remove tcp:7878` or pass `--port 7879` to run on an alternate port.

### Terminal 2: Connect via the Operator Binaries

**On Windows PowerShell:**

```powershell
.\build\bin\na8ve-console.exe --tcp 127.0.0.1:7878
# or for the rich interactive TUI:
.\build\bin\na8ve-tui.exe --tcp 127.0.0.1:7878
```

**On Linux or macOS (POSIX shell):**

```bash
na8ve-console --tcp 127.0.0.1:7878
# or for the rich interactive TUI:
na8ve-tui --tcp 127.0.0.1:7878
```

### Interactive Operator Tour & Verification

Once connected in the TUI (`na8ve-tui`):
1. **Header**: Verify active model status (`cortex-mvp · recurrent int32` or `bx-1m-l2-t036 · recurrent int32`).
2. **Chat (`What grows in bed-1?`)**: Queries SQLite memory, presents the critical context graph (`bed-1 | grows | basil`, `bed-1 | grows | tomatoes`), and autoregressively generates dynamic answers token-by-token.
3. **Model Switching (`/model 3 32`)**: Dynamically loads the 1M parameter model in ~12 ms and updates the status header.
4. **Actuators Panel (F3)**: Displays the 6 compiled actuators (`fan`, `light`, `buzzer`, `pump`, `vent`, `mister`) with live physical states and safety interlocks.
5. **Cortex Graph View (F4)**: Renders the 25 seeded greenhouse facts and their associative relationship graph.
6. **Streaming Telemetry**: Watch continuous `ev tick seq=...` updates and reflex actuation proposals as environmental parameters drift.

## Arduino Uno Q (Arduino App Lab)

`applab/` is this example as an Arduino App Lab app, built on the App Lab Bricks (`arduino:web_ui`, `na8ve:cognitive_os`, `na8ve:memory_graph`, `na8ve:act_policy`). Install it with **Install via USB** on the distribution site's **Apps** page, or package it with the Arduino App Lab SDK ([`sdk/arduino-app-lab/`](../../sdk/arduino-app-lab/README.md)) and import the `.zip` in Arduino App Lab. It runs on a board with the free licence.

- `python/main.py` admits this sandbox, sends it a sensor tick (op `0x20`; on a hot, humid, dry reading the sandbox proposes `act target=fan state=high` and `act target=mister state=on`, which the board's actuator policy table decides), asks the board's model about the same reading, and serves the dashboard through the WebUI brick on port 7000.
- `sketch/sketch.ino` is the STM32U585 sketch. The LED matrix shows what the dashboard shows: the app follows the dashboard's own stream and sends the matrix a line whenever it changes (the reading, each actuator's state, and the policy table's audit count), which scrolls until the next one.
